## 二、开场（痛点，300 字内）

你有没有过这种体验：

打开麦当劳小程序，手里躺着三四张券，逐个往购物车里试。
试到一半发现——"随单购"把价格拉低了，但那张券好像就作废了？
最后付完款，你其实不知道自己到底省没省、省了多少。

更坑的是：**麦当劳的算价接口返回的"优惠金额"是不可信的**。
它会把商品自带促销、甚至会员卡费混进去一起报，
你看到"已优惠 ¥9.10"，实际可能只省了 ¥2.00。

所以我写了 **mcd-butler（麦门管家）**：一条命令，告诉你
**哪张券挂到哪件商品上最划算，以及你究竟省了多少**。

## 三、三个真实踩到的坑（正文骨架，最有传播力的一段）

### 坑 1：价格字段里藏着"条件价"

菜单里同一个商品可能有三个价：`currentPrice`（现价）、`originalPrice`（原价），
以及一个"随单购麦金卡"才有的优惠价。
只信 `currentPrice`，你的计算器会骗人——
那个 ¥29 的四件套，原价其实是 ¥57，需要随单购买卡才成立。

mcd-butler 同时取两个价，并把"需要随单购"标记出来。

### 坑 2：接口不会告诉你真实省了多少

算价接口返回 `discount`，但这个字段把卡费口径也算进去了，
实测一单报 ¥9.10，真实只省了 ¥2.00。

mcd-butler 的口径是 **裸买价 − 到手价**：
先把券全摘掉算一次基准价，再挂上最优券算一次到手价，两者之差才是真金白银。

### 坑 3：券会互相作废

某些情况下，挂了券总价一分不变——因为"随单购"已经把这件降到券面价了。
这张券就是冗余的，占了坑还可能挡住别的券。

引擎会自动识别这类券并明确提示："以下券挂了等于没挂"。

## 四、麦门黄历：别人的黄历是编的，我这张是算的

社区里做麦当劳趣味项目的不少：算命的、测 MBTI 的、生成段子的，都挺好玩。
但我一直觉得差点意思——**那些结论是编的**。

所以我也做了张黄历，区别只有一条：**每一条宜忌背后，都真的打过一次算价接口。**

```
════════ 麦门黄历 · 2026-10-11 周日 · 午市 ════════
  正餐时段，套餐券最全　（本张黄历实打实算了 2 次价）

  宜 · 麦咖啡™美式
      挂「9.9元中杯冰美式」→ 到手 ¥9.90（省 ¥2.00，力度 17%）

  忌 · 全明星双人分享餐八件套
      菜单标 ¥49.90 是「随单购麦金卡优惠」，不满足条件就按 ¥114.50 结 —— 差 ¥64.60

  忌 · BFF四宫格小食盘双人餐
      菜单标 ¥62.90 是「随单购麦金卡优惠」，不满足条件就按 ¥122.50 结 —— 差 ¥59.60
```

「宜」= 这张券挂上去，接口**真的**给我便宜了这么多钱。  
「忌」= 要么没券可挂，要么**挂上去反而更贵**，要么就是上面那种：
菜单标 ¥49.90 看着挺香，其实那是"随单购麦金卡"价，不满足条件按 ¥114.50 结。

**差 ¥64.60。** 这种差价，App 的菜单页不会写，人也不会一条条去核。

三条我自己立的规矩：

1. **时段先说在前头。** 麦当劳大量券是时段券，所以黄历第一行就写清楚
   「早市 / 午市 / 下午茶 / 晚市 / 夜宵」。推荐一张 10:31 就失效的早餐券，等于骗人。
2. **算不出就不写。** 这家门店一张券都挂不上时，黄历会直说"今天算不出宜忌"，
   而不是拿原价凑一条"忌 · 别吃巨无霸"出来充数。
3. **临期券单独喊出来。** 今天/明天到期的券会被点名——作废比花错更可惜。

顺带一提，它还会替你记一本账：`brag` 按**累计真实省钱**给你排段位
（麦门路人 → 学徒 → 信徒 → 执事 → 主教 → 大主教 → 麦门永存），
顺手生成一张能直接粘进朋友圈的纯文本卡片。
账单全部来自本机快照 `~/.mcd-butler/`，不联网、不上传——
一个省钱工具偷偷上传你的消费记录，那才是真离谱。

## 五、它甚至会劝你：这趟别跑了（最强的传播钩子）

算清券之后，还有一笔账没人算：**你要为这单付出多少路程**。

麦当劳的门店接口会返回真实的 `distance`（米）。所以我把"距离"翻译成了
时间和钱，让"省下的优惠"和"跑这一趟的成本"能在同一个数字里比：

```bash
python -m src.cli compare --items "龙焰鸡腿堡三件套,美式" --top 3 --mode taxi
```

真实输出（上海人民广场，距离为接口真值）：

```
出行方式：打车（400 米/分，起步 ¥14.00，每公里 ¥2.50，另计 5 分钟进出店开销）

门店                              距离   来回   到手价    路费     综合
麦当劳上海黄浦华旭国际大厦餐厅     144m   6分   36.80   14.72   57.52
麦当劳上海福州路餐厅              235m   6分   36.80   15.18   57.98
麦当劳上海食品一店餐厅            355m   7分   36.80   15.78   59.58

综合算下来去「麦当劳上海黄浦华旭国际大厦餐厅」最划算。
⚠️ 提醒：这趟路费 ¥14.72 ≥ 券省下的 ¥2.00，等于白跑 —— 除非你本来就要出门。
```

**为了省 2 块钱，花 14 块打车。** 这种账，人脑不爱算，App 更不会告诉你。

几个我自己坚持的取舍：

- 各家到手价一样时（同城同券很常见），它不会装作算出了差别，
  而是直说"价格一样，挑最近的，少走 91 米、少花 2 分钟"。
- 打烊的门店直接剔除 —— 推荐一家关门的店是硬伤。
- 缺货的门店不参与排名，因为拿"有货"和"缺货"比价不公平。
- 时间值不值钱由你定：`--wage` 给了才把等待折成钱，不给就只算真金白银。

## 六、技术方案（给开发者看的一段）

把问题形式化为**二分图匹配**：左边是券，右边是商品，边表示"这张券能挂这件"。

难点在于：算价接口是个**黑盒**，你只能提交一个完整方案、拿回一个总价，
它不会告诉你"这张券值多少钱"。穷举所有挂法又会爆炸（2^n 且要付调用次数）。

做法：

- **贪心** 起手：按券面额从大到小依次挂到能挂的最贵商品上
- **爬山（局部搜索）** 改进，5 个邻域：删券 / 加券 / 挪券 / **换券** / 对调
- **扰动重启**：换个贪心起点再来一轮，跳出局部最优
- **随单购档位**单独作为一个搜索维度（实测这一档往往值好几块，比多爬两步重要）

拿"穷举最优"当标尺量自己：
离线自检里 **80 组随机购物车，命中 94% 的最优组合**（断言阈值 ≥85%，低于这个数 CI 直接红），
其余差距平均不到 ¥0.32，且**绝不超调用上限**。

这个项目还有一条不常见的自我约束：**自检全绿不能证明自检有效。**
`scripts/mutate.py` 会故意把 76 处核心逻辑改坏，再跑一遍自检，
要求每一处都至少有一条断言跟着翻红 —— 第一轮这样试的时候，
60 处里 33 处改坏后自检依然全绿，那些断言守的是运气，不是行为。

## 七、真实实测数据（诚实版）

- 真实账号（上海某门店）实测：购物车 ¥38.80，挂券后 ¥36.80，**真实省 ¥2.00**；
  而接口 `discount` 报的是 ¥9.10（含商品自带促销）。
- 另一单示例：裸买 ¥97.50 → 到手 ¥70.30，省 **27.9%**。

> 必须诚实说明：**省多少取决于你手上有什么券**。
> 券少的账号可能只省几块钱。这个工具保证的是
> "在你现有的券里，找到最省的那一种挂法"，而不是凭空变出优惠。

## 八、30 秒上手

```bash
git clone https://github.com/GenshinKings/mcd-butler.git
cd mcd-butler

# 没 Token 也能先玩（离线演示 + 231 项自检，全程不发一个网络请求）
python -m src.cli demo
python -m src.cli selftest

# 配好 Token 后接真实账号
export MCD_MCP_TOKEN=你的Token
python -m src.cli advise            # 一键顾问：今天该怎么点最划算
python -m src.cli almanac           # 麦门黄历：今天宜吃什么忌吃什么
python -m src.cli brag              # 我的麦门账本与段位（无需 Token，读本机快照）
python -m src.cli optimize --items "板烧鸡腿堡三件套,薯条x2"
python -m src.cli nutrition --kcal 800   # 热量预算内怎么搭最扛饿
python -m src.cli compare --mode taxi    # 该去哪家店、这趟值不值得跑
```

零第三方依赖，Python 标准库就能跑，仓库顶部那个绿色 CI 徽章意味着：
3.10 / 3.13 × Linux / Windows 四种组合上，自检和离线演示都被真跑过一遍了。
