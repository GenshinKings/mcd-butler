## 二、开场（痛点，300 字内）

你有没有过这种体验：

打开麦当劳小程序，手里躺着三四张券，逐个往购物车里试。
试到一半发现——"随单购"把价格拉低了，但那张券好像就作废了？
最后付完款，你其实不知道自己到底省没省、省了多少。

更坑的是：**麦当劳的算价接口返回的"优惠金额"是不可信的**。
它会把商品自带促销、甚至会员卡费混进去一起报，
你看到"已优惠 ¥9.10"，实际可能只省了 ¥2.00。

所以我写了 **mcd-butler（麦门管家）**：一条命令，告诉你
**哪张券挂到哪件商品上最划算，以及你究竟省了多少**。

## 三、三个真实踩到的坑（正文骨架，最有传播力的一段）

### 坑 1：价格字段里藏着"条件价"

菜单里同一个商品可能有三个价：`currentPrice`（现价）、`originalPrice`（原价），
以及一个"随单购麦金卡"才有的优惠价。
只信 `currentPrice`，你的计算器会骗人——
那个 ¥29 的四件套，原价其实是 ¥57，需要随单购买卡才成立。

mcd-butler 同时取两个价，并把"需要随单购"标记出来。

### 坑 2：接口不会告诉你真实省了多少

算价接口返回 `discount`，但这个字段把卡费口径也算进去了，
实测一单报 ¥9.10，真实只省了 ¥2.00。

mcd-butler 的口径是 **裸买价 − 到手价**：
先把券全摘掉算一次基准价，再挂上最优券算一次到手价，两者之差才是真金白银。

### 坑 3：券会互相作废

某些情况下，挂了券总价一分不变——因为"随单购"已经把这件降到券面价了。
这张券就是冗余的，占了坑还可能挡住别的券。

引擎会自动识别这类券并明确提示："以下券挂了等于没挂"。

## 四、技术方案（给开发者看的一段）

把问题形式化为**二分图匹配**：左边是券，右边是商品，边表示"这张券能挂这件"。

难点在于：算价接口是个**黑盒**，你只能提交一个完整方案、拿回一个总价，
它不会告诉你"这张券值多少钱"。穷举所有挂法又会爆炸（2^n 且要付调用次数）。

做法：

- **贪心** 起手：按券面额从大到小依次挂到能挂的最贵商品上
- **爬山（局部搜索）** 改进，5 个邻域：删券 / 加券 / 挪券 / **换券** / 对调
- **扰动重启**：换个贪心起点再来一轮，跳出局部最优
- **随单购档位**单独作为一个搜索维度（实测这一档往往值好几块，比多爬两步重要）

拿"穷举最优"当标尺量自己：
离线自检里 **80 组随机购物车，命中 94% 的最优组合**（断言阈值 ≥85%），
其余差距平均不到 ¥0.32，且**绝不超调用上限**。

## 五、真实实测数据（诚实版）

- 真实账号（上海某门店）实测：购物车 ¥38.80，挂券后 ¥36.80，**真实省 ¥2.00**；
  而接口 `discount` 报的是 ¥9.10（含商品自带促销）。
- 另一单示例：裸买 ¥97.50 → 到手 ¥70.30，省 **27.9%**。

> 必须诚实说明：**省多少取决于你手上有什么券**。
> 券少的账号可能只省几块钱。这个工具保证的是
> "在你现有的券里，找到最省的那一种挂法"，而不是凭空变出优惠。

## 六、30 秒上手

```bash
git clone https://github.com/GenshinKings/mcd-butler.git
cd mcd-butler

# 没 Token 也能先玩（离线演示 + 50 项自检）
python -m src.cli demo
python -m src.cli selftest

# 配好 Token 后接真实账号
export MCD_MCP_TOKEN=你的Token
python -m src.cli advise            # 一键顾问：今天该怎么点最划算
python -m src.cli optimize --items "板烧鸡腿堡三件套,薯条x2"
python -m src.cli nutrition --kcal 800   # 热量预算内怎么搭最扛饿
```

零第三方依赖，Python 标准库就能跑。
